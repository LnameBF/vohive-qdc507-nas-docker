# VoHive QDC507：绿联 NAS 逐步部署指南

这份指南按“下载现成镜像、导入绿联 Docker、创建项目”的方式编写。照着“必做”部分操作即可，不需要编译源码，也不需要给模块刷固件。

## 一、先分清每个文件的用途

| 文件 | 用途 | 是否导入 |
|---|---|---|
| `vohive-qdc507-0.2.1-amd64.tar` | 已构建好的 Docker 镜像 | **导入到 Docker 的“镜像”页面** |
| `SHA256SUMS.txt` | 检查 TAR 是否完整 | 不导入；可选校验 |
| `compose.import.yml` | 使用已导入镜像创建 VoHive 项目 | **创建项目时使用** |
| `compose.yml` | 在有 Docker 构建能力的 Linux 主机上从源码构建 | 普通绿联 NAS 不使用 |
| `compose.ugreenlink.yml` | 可选的绿联 Quick Access 反向代理 | 只有需要 Quick Access 时才使用 |
| `Dockerfile`、`third_party/`、`scripts/` | 源码和构建材料 | 普通部署不需要逐个导入 |
| `README.md`、本文件 | 使用说明 | 不导入 |

最容易记住的一句话：**TAR 导入“镜像”；`compose.import.yml` 用来“创建项目”；其他文件先不要碰。**

## 二、必做准备

1. 绿联 NAS 必须是 amd64/x86-64 架构，并已安装 Docker 应用。
2. DJI 第一代 4G 模块直接插在 NAS 的 USB 口。
3. 如果还保留虚拟机备份，部署前先关机，不能让虚拟机和 Docker 同时占用模块。
4. 给 NAS 预留 1 GB 以上空间用于镜像和运行数据。

本项目运行在 NAS 上，不修改模块固件，也不需要导入任何模块固件。

## 三、最简单的导入部署（推荐）

### 1. 下载两个文件

打开 [v0.2.1 Release](https://github.com/hei85/vohive-qdc507-nas-docker/releases/tag/v0.2.1)，下载：

- `vohive-qdc507-0.2.1-amd64.tar`
- `compose.import.yml`（在仓库主页打开后点“Raw”下载，或复制文件内容）

`SHA256SUMS.txt` 只是校验文件，不是 Docker 镜像，不要拿它导入。

### 2. 把 TAR 导入 Docker 镜像

在绿联 Docker 应用中：

1. 打开左侧“镜像”。
2. 点击“导入”或“从电脑导入”。
3. 选择刚才下载的 `vohive-qdc507-0.2.1-amd64.tar`。
4. 等待导入完成；镜像名称应显示为 `local/vohive-qdc507:0.2.1`。

这里导入的是 **TAR 镜像文件**，不是 `compose.import.yml`。

### 3. 用 `compose.import.yml` 创建项目

在绿联 Docker 应用中：

1. 打开左侧“项目”。
2. 点击“创建”或“新建项目”。
3. 如果有“从电脑导入”，选择 `compose.import.yml`；如果只有文本编辑框，就新建项目后把该文件的全部内容粘贴进去。
4. 项目名称可以填写 `vohive`。
5. 点击“部署/创建”。

不要在这一步选择 `compose.yml`：它会尝试现场编译镜像；已经导入 Release TAR 时必须使用 `compose.import.yml`。

### 4. 打开后台

项目显示“运行中”后，浏览器打开：

```text
http://NAS的局域网IP:7575
```

例如 NAS 的地址如果是 `192.168.1.100`，就是 `http://192.168.1.100:7575`。这里的地址必须换成使用者自己的 NAS 地址，不能照抄示例。

首次登录：

- 用户名：`admin`
- 密码：`vohive`

登录后立即在后台修改密码。Release 不包含任何人的现有密码或运行数据。

## 四、确认模块是否被识别

进入 Docker → 容器 → `vohive-qdc507` →“终端”，打开 `/bin/bash`，执行：

```sh
verify-qmi
```

正常情况下至少能看到一个 `/dev/cdc-wdm0`（编号也可能是其他数字），并能看到 `qmi_wwan`、`cdc_wdm`、`option` 驱动。

如果网页能打开但设备显示“等待设备重新枚举”，先等待 10～30 秒。仍没有设备时检查：

- 模块是否插牢、供电是否足够；
- 虚拟机是否仍占用 USB；
- NAS 内核是否提供 `qmi_wwan`、`cdc_wdm`、`option`；
- 是否把 `compose.import.yml` 完整导入，尤其不能删除 `privileged`、`network_mode` 和 `/dev`、`/sys`、`/lib/modules` 映射。

## 五、热插拔测试

保持项目运行，拔下模块，等待 5 秒后插回同一个 USB 口。通常 10～30 秒内会重新出现设备，不需要重建项目。若超过 1 分钟仍未恢复，先在终端运行 `verify-qmi`，再查看容器日志。

## 六、需要绿联 Quick Access 时（可选）

主 VoHive 容器使用 host 网络，才能稳定访问 USB/QMI；部分绿联版本的“快速访问”只代理 bridge 容器。因此 Quick Access 是第二个可选容器，不替代主容器。

1. 先按上面步骤部署并运行 `vohive-qdc507`。
2. 创建第二个项目时使用 `compose.ugreenlink.yml`，不要用它替代 `compose.import.yml`。
3. 该文件会使用 `caddy:2-alpine` 并暴露 NAS 的 `37953` 端口。
4. 在绿联 Docker 的 Quick Access 中打开这个代理容器，再进入 VoHive 页面。

如果只在局域网使用，不需要部署这个可选代理。不要把 7575 或 37953 端口直接暴露到公网。

## 七、源码构建（普通部署不需要）

只有在 Linux 主机具备 Docker 构建能力时才使用：

```sh
docker compose -f compose.yml up -d --build
```

构建完成后可以导出：

```sh
./scripts/export-image.sh vohive-qdc507-0.2.1-amd64.tar
```

导出的 TAR 再按第三节导入绿联 Docker。

## 八、更新和保留数据

更新镜像时，只替换镜像并重新部署项目；不要删除项目目录下的 `runtime/data` 和 `runtime/logs`。这两个目录保存运行配置和日志。若要重置为全新安装，应先在 Docker 中停止项目并备份后再处理这些目录。
