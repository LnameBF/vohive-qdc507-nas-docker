# 使用指南：绿联 NAS / amd64 Linux

## 你需要准备的东西

- 一台 amd64 Linux 或绿联 NAS；内核需要有 `qmi_wwan`、`cdc_wdm`、`option` 驱动。
- 支持的 QDC507 USB 4G 模块，直接插在 NAS USB 口。
- Docker 应用。若同时保留虚拟机备份，虚拟机必须关机，避免占用同一个 USB 模块。

本项目不向模块刷写任何固件；也不需要导入模块固件。

## 最简单的 NAS 部署方式

1. 从 GitHub Releases 下载 `vohive-qdc507-0.2.0-amd64.tar`。
2. 进入绿联 Docker 的“镜像”，选择“从电脑导入”，导入该 TAR。
3. 进入“项目”，新建项目；将仓库中的 `compose.import.yml` 内容粘贴进去后部署。
4. 等待约一分钟，在浏览器打开 `http://NAS_IP:7575`。
5. 首次登录账号为 `admin`，密码为 `vohive`。登录后立即在后台修改密码。

首次部署会自动启动。模块被拔出再插回后，等待约 10～30 秒即可自动恢复；无需重建项目。

## 从源码构建

在 Linux 主机克隆仓库后执行：

```sh
docker compose -f compose.yml up -d --build
```

构建完成后，导出镜像供 NAS 导入：

```sh
./scripts/export-image.sh vohive-qdc507-0.2.0-amd64.tar
```

## 外网访问（可选）

主服务必须使用 host 网络来访问 QMI 硬件。若 NAS 的 Quick Access 仅支持 bridge 容器，可单独部署 `compose.ugreenlink.yml`。然后通过它的快速访问入口进入后台；不要直接把管理后台暴露到公网。

## 判断模块是否已恢复

在 VoHive 容器终端运行：

```sh
verify-qmi
```

看到 `/dev/cdc-wdm0`（或其他 `cdc-wdm` 节点）即说明 QMI 控制通道已准备好。若一直没有该节点，问题在 NAS 内核驱动或 USB 供电，而不是网页或账号。
